# Open-source reference corpus (KF-DQ-012.2)

A public regression corpus for Kritva Forge. It is built from five
open-source Apache-2.0 repositories, pinned as git submodules. The complete
pipeline and every gate run on it locally, without the private
`kritva-forge-data` repository.

**Boundary.** The reference corpus is a separate corpus. It does **not**
replace `kritva-forge-data`, which stays authoritative for datasets, splits
and published baselines. The public repository heads differ from the
private corpus files, so the numbers are not comparable.

## Layout

```text
reference/
  corpus.yaml          single source of truth: per IP the submodule, pinned commit, license,
                       explicit file list, include dirs, exclusions and documented external includes
  sources/             git submodules (pinned, read-only)
    qspim/ rtc/ fpu/ security_core/ ycr1cr/
  expected/
    summary.json       committed regression baseline (generated by make reference-baseline)

build/reference/                     generated, gitignored
  CORPUS_KIND                        "reference" (explicit corpus marker)
  reference_manifest.json            sources, commits, files and sha256 (evidence)
  kritva-forge-data/                 exact kritva-forge-data layout = DATA_ROOT
    raw/rtl/original/<ip>/...        byte-identical copies + files.f
```

The IP ids are `aes` (security_core), `fpu`, `qspi` (qspim), `rtc` and
`ycr1` (ycr1cr). `ycr1` is deliberately not called `yifive`, which is the
private ycr2-based IP.

## Commands

```bash
make reference-init         # check out the pinned submodules
make reference-regression   # materialize, then pipeline + data-quality on build/reference/kritva-forge-data,
                            # then compare with reference/expected/summary.json and prove the sources are unchanged
make reference-clean        # remove build/reference
```

These are the production entry points; only `DATA_ROOT` differs. For a
single step:

```bash
make reference-data
make pipeline     DATA_ROOT=$PWD/build/reference/kritva-forge-data
make data-quality DATA_ROOT=$PWD/build/reference/kritva-forge-data
```

Corpus tests that assert private-corpus constants (19 IPs, 350 modules, FSM
and output counts, and so on) skip on this root. They are identified by the
`CORPUS_KIND` marker.

## Rules

- Every materialized file is listed in `corpus.yaml`; nothing is discovered.
- Every `` `include `` must resolve inside the IP. Anything else is either:
  - a documented **exclusion** (the file is not materialized), e.g.
    `qspim/src/qspim_top.sv` needs the parent SoC's `user_reg_map.svh`; or
  - a documented **external include**, e.g. `ycr_arch_custom.svh`, which is
    only used under an undefined `` `ifdef``.

  Any other missing include fails. No RTL is ever fabricated.
- Submodules must be at their pinned commit and clean. Nothing is written
  into `reference/sources`; the regression proves this.

## Updating the baseline

Any change to a pinned commit, the file selection, an include directory, an
exclusion, or Forge behaviour that changes the reference outputs needs a new
baseline:

```bash
make reference-baseline     # rewrites reference/expected/summary.json
git diff reference/expected/summary.json
```

Review the diff in the pull request. `make reference-regression` never
updates the baseline.
